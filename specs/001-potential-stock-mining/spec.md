# Feature Specification: 潜力标的智能挖掘系统 (Potential Stock Mining)

**Feature Branch**: `001-potential-stock-mining`

**Created**: 2026-06-20

**Status**: Draft

**Input**: User description: "A股产业增量潜力标的智能挖掘系统 — 以公告事件为触发、基本面为底盘、
产业增量为核心判断标准的自动化标的筛选工具，合并在现有DSA框架中，新增功能入口供手动触发。"

## Clarifications

### Session 2026-06-20

- Q: 系统是否需要解析公告 PDF 附件正文来提取交易细节，还是仅基于标题进行事件分类？→ A: 仅标题分类（Phase 1）。PDF 正文解析（含 OCR）延后至后续迭代。已更新 Assumptions 和 Edge Cases。
- Q: 首次部署时是否需要回扫历史公告？回扫多长时间？→ A: 首次仅回扫近 30 天公告，不进行全量历史回溯。已更新 Assumptions。
- Q: 定时扫描进行中时用户手动触发，行为是排队还是拒绝？→ A: 拒绝并提示"已有扫描任务正在执行"，不排队。已更新 Edge Cases。
- Q: 筛选结果是否需要文件导出功能（下载 Markdown/CSV）？→ A: 不需要文件导出。仅在 Web 页面展示 + CLI 终端输出 + 定时邮件推送。已更新 FR-007 和 Assumptions。
- Q: 邮件推送形式是逐条实时还是每日汇总？→ A: 每日汇总推送（定时扫描完成后一条简报包含当日所有新增标的）。已更新 Assumptions。

### User Story 1 — 定时自动扫描公告并筛选潜力标的 (Priority: P1)

作为投研用户，系统每个交易日盘后自动扫描全市场公告，识别跨界转型、产能扩张、
并购整合等事件信号，经过基本面过滤和产业价值评分后，输出当日新增潜力标的清单，
无需人工逐份阅读公告。

**Why this priority**: 自动化定时巡检是系统的核心价值 — 替代人工巡检，
解决信息覆盖不全和效率低下的问题，是其他所有功能的基础。

**Independent Test**: 可以独立测试：配置一个已知有重大并购公告的交易日，
系统运行后验证是否输出了对应的潜力标的条目，且报告结构符合预期。

**Acceptance Scenarios**:

1. **Given** 系统已配置自选时间段，**When** 到达定时巡检时间，
   **Then** 系统自动拉取该时间段内全量公告，完成信号识别、基本面过滤和评分，
   并生成当日潜力标的简报。
2. **Given** 当日无新增有效信号，**When** 自动化流程执行完毕，
   **Then** 系统输出空报告并注明"当日无新增潜力标的"。
3. **Given** 公告数据源暂时不可用，**When** 定时任务触发，
   **Then** 系统记录错误日志，触发失败告警通知，不影响其他分析流程。

### User Story 2 — 手动触发潜力标的挖掘 (Priority: P1)

作为投研用户，我可以随时在 Web 工作台或通过 CLI 命令手动触发潜力标的挖掘流程，
指定特定时间范围或特定股票代码进行定向扫描，不需要等待定时任务。

**Why this priority**: 用户明确要求"新增一个功能入口供我手动触发"，
这是系统集成到现有 DSA 框架的关键交互入口。

**Independent Test**: 可以独立测试：通过 CLI 运行指定日期范围的扫描命令，
验证系统仅扫描该时间段的公告并输出结果；Web 界面点击"立即分析"按钮后
能观察到任务进度和结果展示。

**Acceptance Scenarios**:

1. **Given** 用户有权限手动触发分析，**When** 用户在 Web 工作台点击
   "潜力标的挖掘"功能入口并选择"立即分析"，**Then** 系统开始执行
   全量扫描流程，并在完成后在页面展示结果摘要。
2. **Given** 用户通过 CLI 执行 `python main.py --potential-stock-mining`
   命令，**When** 命令执行完毕，**Then** 控制台输出本次扫描的潜力标的清单。
3. **Given** 用户手动触发时指定了时间范围（如 `--since 2026-06-01`），
   **When** 系统执行扫描，**Then** 仅拉取指定时间后的公告进行分析。

---

### User Story 3 — 查看与跟踪潜力标的清单 (Priority: P2)

作为投研用户，我可以在 Web 工作台中查看历史潜力标的清单，包括触发事件、
核心逻辑、风险提示、优先级分级，并对标的进行纳入观察、跟踪、剔除等状态管理。

**Why this priority**: 筛选结果需要有持久化的查看和管理能力，但核心价值在
自动化筛选本身，因此列为 P2。

**Independent Test**: 可以独立测试：手动构造几条筛选结果写入数据库，
验证 Web 页面能正确展示清单，且状态切换操作生效。

**Acceptance Scenarios**:

1. **Given** 系统已有历史筛选结果，**When** 用户打开潜力标的清单页面，
   **Then** 按日期倒序展示标的列表，每条包含触发事件类型、标的名称、
   评分和状态标签。
2. **Given** 用户查看某条标的详情，**When** 点击"纳入观察"或"剔除"，
   **Then** 标的状态更新，并在清单中反映最新状态。

---

### User Story 4 — 赛道定向挖掘 (Priority: P3)

作为投研用户，我可以指定特定产业赛道（如 AI+药物研发、AI 算力上游材料等），
系统定向筛选该赛道相关的跨界转型标的，并支持历史回溯验证。

**Why this priority**: 赛道定向挖掘是进阶功能，依赖产业知识库的完善程度，
在基础定时扫描功能稳定后迭代。

**Independent Test**: 可以独立测试：配置一个已知的赛道关键词和一支匹配的
历史公告标的，运行赛道定向扫描，验证标的被正确命中。

**Acceptance Scenarios**:

1. **Given** 用户指定赛道"AI 算力上游材料"，**When** 执行赛道定向挖掘，
   **Then** 系统扫描全量公告并筛选出与该赛道相关的事件标的。
2. **Given** 用户选择历史时间段回溯，**When** 执行回溯扫描，
   **Then** 系统仅扫描该时间段的公告并输出历史期的潜力标的清单。

### Edge Cases

- **公告数据源不可用**：巨潮资讯或交易所数据源临时中断时，系统应记录错误、
  触发告警，但不影响现有其他分析流程（大盘分析、个股分析）。
- **无新增信号**：当日全量公告均不命中任何触发信号类型时，输出空报告，
  注明"当日无新增潜力标的"。
- **基本面数据缺失**：某只标的财务数据不全时，应标记为"数据不足"而非剔除，
  并在报告中注明缺失项。
- **同一标的多次触发**：同一家公司短期内多次触发不同事件（如先发公告、
  后发进展），应合并为同一标的跟踪记录，避免重复输出。
- **手动触发与定时任务并发**：用户手动触发时若定时任务正在执行，
  应拒绝新请求并提示"已有扫描任务正在执行"，不排队。
- **公告 PDF 解析失败**（Phase 2+ 适用）：部分公告附件为扫描件或格式异常导致解析失败时，标记为"解析失败"并记录，跳过该公告继续处理其余公告。Phase 1 不使用 PDF 正文解析，因此该场景不适用。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持每日盘后定时自动扫描全市场 A 股公告，默认执行时间
  可配置（如 18:00 北京时间），并可配置增量轮询频率。
- **FR-002**: 系统 MUST 提供手动触发入口，包括 CLI 命令
  `python main.py --potential-stock-mining` 和 Web 工作台功能页面，
  支持指定 `--since` / `--until` 时间范围参数。
- **FR-003**: 系统 MUST 支持公告信号自动识别，覆盖以下事件类型：
  并购重组（P0）、产能扩张（P0）、业务变更（P1）、技术合作（P1）、
  订单落地（P2），并按优先级分级。
- **FR-004**: 系统 MUST 对初筛标的执行基本面质量过滤，至少评估：
  财务健康度（营收、利润、现金流、资产负债率）、治理与执行力
  （实控人/管理层信用记录）、估值安全边际（历史分位、市值弹性）。
- **FR-005**: 系统 MUST 对通过基本面过滤的标的进行产业增量价值评估，
  评估维度包括：赛道空间、业务协同性、行业格局影响、业绩弹性。
- **FR-006**: 系统 MUST 内置伪转型甄别规则，自动降权或剔除满足以下特征的标的：
  主业与新赛道完全割裂、转型集中在行情火热期、落地形式为空壳公司/
  框架协议、研发费率极低且无核心技术储备。
- **FR-007**: 系统 MUST 输出标准化分析报告，包含：触发事件概述、
  公司原有基本面、事件方案细节、新赛道产业分析、增量价值分析、
  未来展望与风险提示。报告以 Markdown 格式存储于 JSON 文件，
  在 Web 页面渲染展示，并通过定时邮件推送。
- **FR-008**: 系统 MUST 支持潜力标的池管理，包括状态标记：
  观察中、跟踪中、已剔除，并支持查看历史筛选记录。
- **FR-009**: 系统 MUST 支持产业知识库管理，预设 AI 算力上游、AI+医疗、
  AI+药物研发等默认赛道，支持新增赛道和产品映射关系的编辑。
- **FR-010**: 系统 MUST 支持赛道定向挖掘，用户可指定赛道关键词筛选标的，
  并支持历史公告回溯验证。
- **FR-011**: 系统 MUST 提供筛选规则和阈值配置界面（Web 或配置文件），
  支持自定义财务指标阈值、事件触发关键词和排除规则。
- **FR-012**: 系统 MUST 与现有 DSA 框架集成，不破坏现有大盘分析、个股分析、
  通知推送等功能的正常运行，单一模块失败不影响其他模块。

### Key Entities

- **Announcement**：原始公告记录（股票代码、公告标题、发布时间、公告类型、
  PDF 附件链接、解析后的正文摘要、打标结果）
- **ScreeningResult**：筛选结果（标的代码、触发事件类型、信号优先级、
  基本面评分、产业价值评分、综合评级、报告 Markdown、创建时间）
- **TrackedTarget**：跟踪标的（标的代码、状态：观察/跟踪/剔除、
  纳入时间、剔除原因、关联的 ScreeningResult 列表）
- **IndustryKnowledgeBase**：产业知识库（赛道名称、产业链环节描述、
  核心产品列表、技术路线、对应公司映射、最后更新时间）
- **ScreeningRule**：筛选规则（规则名称、类型：事件规则/基本面规则/
  排除规则、规则参数、启用/禁用状态）
- **ScanTask**：扫描任务（任务 ID、触发方式：定时/手动、执行状态、
  开始时间、完成时间、扫描时间段、扫描范围、错误日志）

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 定时扫描任务在盘后 2 小时内完成全量公告解析与筛选；
  增量公告在发布后 15 分钟内完成识别。
- **SC-002**: 核心事件信号识别准确率 ≥ 90%（以人工复核结果为基准，
  抽样周期为两周）。
- **SC-003**: 手动触发功能从用户点击/输入命令到开始扫描的响应时间
  不超过 5 秒。
- **SC-004**: 用户可通过 Web 工作台或 CLI 两种入口完成手动触发分析。
- **SC-005**: 每日定时任务运行成功率 ≥ 99%，异常时自动发送告警通知。
- **SC-006**: 手动触发与定时任务可同时配置，互不干扰；并发请求时
  自动排队或提供状态提示。

## Assumptions

- **公告数据源**：优先对接巨潮资讯网（cninfo.com.cn），通过公开接口
  或已有数据源获取；若不可用则降级使用备选数据源，降级逻辑复用
  现有的 data provider fallback 机制。
- **公告解析深度**：Phase 1 仅基于公告标题进行事件分类和信号识别，
  不解析 PDF 附件正文。PDF 正文解析（含 OCR）延后至后续迭代。
- **数据存储**：筛选结果、跟踪标的使用 JSON 文件存储（无数据库依赖），
  存储引擎为 `MiningFileStore`。`data/potential_stock_mining/` 目录管理
  所有运行时数据。
- **首次部署**：首次部署时回扫近 30 天公告以构建初始数据池，不进行
  全量历史回溯。用户后续可通过 `--since` 参数手动扩展回扫范围。
- **基本面数据**：复用现有 DSA 系统的财务数据和行情数据基础设施，
  不新增独立数据源。
- **产业知识库**：初始版本以 YAML/JSON 配置文件形式维护，后续可考虑
  迁移到数据库。预设 AI 算力上游、AI+医疗、AI+医药三个默认赛道。
- **Web 入口**：在现有 DSA Web 工作台新增「潜力标的挖掘」导航项，
  包含手动触发按钮和结果列表页面。
- **CLI 入口**：新增 `--potential-stock-mining` CLI 参数，遵循现有
  `main.py` 的参数风格。
- **通知**：筛选结果不默认推送，用户可配置是否通过现有通知渠道（含邮件）
  接收每日标的简报。简报为每日汇总形式（定时扫描完成后一条推送包含当日
  所有新增标的），内容为标准化分析报告（Markdown 格式）。不支持逐条实时推送。
- **导出**：不提供文件导出功能（Markdown 下载、CSV 等）。报告在 Web 页面
  展示、CLI 终端输出、或通过邮件推送；用户可通过 CLI 重定向保存终端输出。
- **存储**：筛选结果和跟踪状态以 JSON 文件形式存储在 `data/potential_stock_mining/` 目录，不依赖数据库。由 `MiningFileStore` 管理读写。
